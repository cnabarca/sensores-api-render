Monitoreo de drift sobre un lote de lecturas

Se simula un lote (por ejemplo, un turno) y se compara con la línea base sana del motor mediante cuatro capas: drift estadístico (prueba K-S), límites k·σ, zonas normativas y modelo de ML. Es la evolución de la regla ±2σ de la guía, ahora con tres variables. El reporte visual de Evidently se genera bajo demanda para no penalizar la latencia en una instancia de 0,1 CPU.

Simulación de degradación hasta la falla

Un rodamiento empieza a desgastarse el día 20 y falla el día 56. Cada día el panel consulta GET /trayectoria/{dia} y la API evalúa las 144 lecturas del motor (una cada 10 minutos). Observa cuántos días de anticipación ofrece cada capa del sistema.
